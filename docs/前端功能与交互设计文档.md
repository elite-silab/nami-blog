# 前端功能与交互设计

## 目标

Nami Blog 的前端面向阅读者与个人站长，重点是：

- 文章读取快，结构清楚，移动端可用
- 内容发布后立即可见
- 后台操作有明确的加载、成功和失败反馈
- 新手不需要理解多个服务地址
- 无障碍和键盘操作不作为事后补丁

## 技术边界

- Next.js 16 App Router
- React 19 Server/Client Components
- Tailwind CSS 4
- OpenNext for Cloudflare
- Web 与 Hono API 同一个 Worker、同一个 Origin
- 服务端组件直接调用内嵌 Hono，不对自身 Worker 发公网请求

## 信息架构

```text
/
├── /blog
│   ├── /blog/page/:page
│   ├── /blog/:slug
│   ├── /blog/category/:slug
│   └── /blog/tag/:slug
├── /search
├── /friends
├── /about
├── /rss.xml
├── /sitemap.xml
└── /admin/*
```

公开页面与管理后台共享主题 Token，但后台使用独立 Shell。访问 `/admin` 时，公开站点 Header/Footer 不显示。

## 首页

首页由三部分构成：

1. 品牌与主行动：最新文章、关于页面
2. 置顶/最新文章焦点卡
3. 最近文章与分类入口

首页顶部标语、主标题、强调标题、简介和两个按钮的文字可在后台分别修改。版式和按钮去向保持固定，避免误操作破坏响应式布局；没有保存自定义内容时继续使用项目当前文案。

文章、分类和首页文案以 D1 为准，通过可降级的 KV 公开缓存读取。没有内容时显示明确空状态，不输出空白布局。

## 关于页

- 正文由管理员在“站点设置”中使用 Markdown 编辑
- 支持与文章正文一致的标题、列表、引用、链接、图片、表格和代码块
- Markdown 在服务端渲染并经过 HTML 允许列表清理
- 未保存自定义内容时，根据当前站点名称、副标题、GitHub 和邮箱生成默认介绍
- 保存后清理公开 KV 缓存，后续访问立即读取新内容

## 文章列表

- 每页固定数量，使用服务端分页
- 展示标题、摘要、封面、发布日期和分类/标签信息
- 分类和标签页面复用统一列表组件
- 页码非法或超出范围时给出可恢复入口
- 文章卡片整体可点击，键盘焦点清晰

## 文章详情

- 服务端读取公开且已发布文章
- 设置 title、description、canonical 和 Open Graph
- 展示发布日期、字数、阅读量、分类和标签
- 正文使用 GFM Markdown 渲染，支持标题、列表、引用、链接、图片、表格和代码块
- 提供上一篇/下一篇与分享入口
- 评论开关关闭时完全隐藏评论区

### 阅读统计

文章 GET 请求不增加阅读量。浏览器加载成功后向 `/api/v1/posts/:slug/view` 上报；同一标签页对同一文章只上报一次。

### 正文安全

文章始终以 D1 中的 `content` Markdown 源文为准。Next.js 服务端渲染时将 Markdown 转为 HTML，再通过允许列表清除脚本、事件属性和危险协议；文章页和 RSS 共用同一条渲染链路。旧文章无需重新保存即可使用新的渲染规则。

## 搜索

- URL 使用 `?q=` 保存关键词，可复制和后退
- 空关键词不发请求
- 显示加载、空结果和失败状态
- `Ctrl/Command + K` 聚焦搜索框
- 请求同源 `/api/v1/posts`

## 评论

- 昵称必填，邮箱不公开，网址可选
- 隐藏蜜罐字段过滤简单机器人
- 支持回复与嵌套展示
- 提交中禁用按钮
- 自动批准时刷新列表；待审核时明确告知用户
- 评论关闭时 UI 隐藏，API 同时拒绝写入

## 友链

友链由管理员直接维护并立即公开。公开页只返回展示所需字段，不暴露历史审核状态。

- 手机端单列、平板和桌面端双列，不产生页面级横向滚动
- 卡片展示名称、域名、完整介绍和明确的外链提示
- 长中文、英文、URL 与 Emoji 均允许自然换行
- 外部头像加载失败时回退为站点名称首字，不显示破图
- 空状态说明友链会在站长添加后立即出现

## Header 与移动菜单

- 桌面端显示文章、友链、关于、搜索、RSS、明暗模式
- 移动端使用可展开菜单
- 当前栏目具有可见状态
- 菜单按钮包含 `aria-label` 与 `aria-expanded`
- 页面包含“跳到主要内容”链接

## 主题

站点提供樱花、海洋、星空三套主题，主题由 D1 的 `site_theme` 决定。管理员在设置页点击卡片时即时预览，保存后清理公开 KV 缓存，访客请求通常立即使用新主题。

明暗模式是访客偏好，保存在 `localStorage`。Head 内初始化脚本在首次绘制前应用偏好，减少颜色闪烁。

## 弹窗规范

分类、标签和友链编辑统一使用：

- `fixed inset-0` 全屏遮罩
- CSS Grid 居中
- 移动端保留 16px 安全边距
- 最大宽度限制
- 点击遮罩、关闭按钮或取消关闭
- 不使用顶部彩色装饰条
- 标题、关闭按钮和首个输入框形成清晰焦点顺序

弹窗不得依赖父级 `position`，以避免出现在网页左上角。

## 状态反馈

所有异步操作至少覆盖：

- 初始状态
- 加载中
- 成功
- 可理解的失败信息
- 可恢复操作（重试、返回列表或保留输入）

“保存成功”与“发布成功”需要区分。单 Worker 架构中公开内容保存后提示“前台已更新”，同时清理公开 KV 缓存，不显示部署进度。

## 性能策略

- 公共内容使用 Server Components，减少客户端 JavaScript
- 只有搜索、评论、阅读统计、主题切换和后台表单使用 Client Components
- 内部 API 直接进程内调用 Hono
- 动态内容不依赖构建时抓取
- 封面图使用固定宽高比，避免布局跳动
- RSS 最多读取最近文章，Sitemap 覆盖公开路由

未来接入 Next Image 前，必须明确允许的远程图片域名，避免开放任意图片代理。

## SEO

`NEXT_PUBLIC_SITE_URL` 是正式公开地址，生产默认：

```text
https://nami-blog.codeelite.workers.dev
```

它用于 canonical、分享、RSS、Sitemap 和 robots。绑定自定义域名后修改该值并部署一次。

站点名称和描述以 D1 为准；后台修改后清理公开 KV 缓存，Metadata 在后续请求读取新值。

## 无障碍验收

- 键盘可到达所有交互元素
- 表单输入有 label 或 aria-label
- 按钮不使用无语义 div
- 焦点样式不被移除
- 文本与背景对比度满足 WCAG AA
- 动态状态使用 `aria-live` 或可见文本
- 图像提供有意义的 alt；纯装饰图使用空 alt

## 响应式断点

- 小屏优先，默认单列
- `sm`：表单和导航增强
- `md`：文章列表双列
- `lg`：后台固定侧栏
- `xl`：编辑器正文与发布设置双栏

不允许通过固定桌面宽度制造横向滚动。

## 验收路径

1. 首页 → 文章列表 → 文章详情 → 评论
2. 搜索关键词 → 打开结果 → 返回搜索
3. 分类/标签 → 分页
4. 后台登录 → 新建草稿 → 恢复草稿 → 发布 → 前台立即可见
5. 新建分类/标签，确认弹窗居中
6. 修改主题和评论开关，确认访客侧实时变化
7. 修改首页文案和关于页 Markdown，确认前台即时更新
8. 移动端打开、关闭后台侧栏与前台菜单
9. 友链页检查长描述、失效头像以及手机端横向溢出
