# ADR-0003：使用 KV 作为可降级的公开读缓存

## 状态

已接受

## 背景

Nami Blog 已使用 Next.js、Hono 和 D1 运行在单个 Cloudflare Worker。公开页面由服务端动态读取 D1，因此内容保存后无需重新部署，但首页、文章页、分类、标签、友链、RSS 和 Sitemap 的热门访问会重复执行相同查询。

项目仍面向个人站长和第一次使用 Cloudflare 的用户。缓存不能成为数据源，不能增加新的密钥配置，也不能让 KV 故障导致博客或后台不可用。

## 决策

在同一个 Worker 中增加名为 `CACHE` 的 Workers KV binding，作为可删除、可重建、可降级的公开读缓存。

- D1 是文章、分类、标签、友链和站点设置的唯一真数据源。
- KV 仅保存已发布、公开且不含访客隐私的数据。
- 非搜索文章列表、文章详情、分类、标签、友链和公开设置使用 cache-aside。
- 搜索、草稿、后台、认证、评论隐私、浏览量写入和网站备份不进入 KV。
- 后台响应声明 `publication.status = live` 时，统一清除版本化公开缓存前缀。
- KV 缺失或操作失败时直接读取 D1；缓存失败不能改变 D1 写入结果。
- 响应使用 `X-Nami-Cache` 表示 `HIT`、`MISS` 或 `BYPASS`，便于排查但不暴露内部数据。

## 后果

### 正面影响

- 热门公开页面减少重复 D1 查询。
- KV 命中可以缩短跨地域公开读取路径。
- D1 暂时读取异常时，已缓存公开内容仍有机会正常返回。
- 本地开发与未绑定 KV 的环境仍可完整运行。

### 负面影响

- KV 是最终一致存储，后台修改后不同地区可能短时间看到旧缓存。
- 需要维护 TTL、key 版本和失效测试。
- Worker 增加一个 Cloudflare 存储 binding，部署清单比仅 D1 多一项。

### 中性影响

- 缓存内容可以随时删除，不纳入网站备份。
- 管理员写入频率很低，公开内容变更时采用整组失效，优先保持实现简单可靠。

## 备选方案

### 继续只使用 D1

实现最简单，但热门页面仍重复执行相同联表查询，无法利用 KV 的全球读优势。

### 将文章主数据迁移到 KV

KV 不适合关系查询和强一致管理写入，会破坏现有分类、标签、评论与备份模型，因此不采用。

### 用 KV 记录浏览量或严格限流

KV 不提供适合该场景的强一致原子计数，且会产生大量写入。浏览量继续使用 D1；严格限流未来应评估 Cloudflare Rate Limiting 或 Durable Objects。
