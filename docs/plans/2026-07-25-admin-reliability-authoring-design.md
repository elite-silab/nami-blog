# 管理端可靠性与写作体验设计

## 背景与目标

Nami Blog 使用 Astro 静态构建部署到 Cloudflare Pages，管理 API 独立运行在 Workers。当前核心流程有两个结构性断点：Astro 的动态管理页只会在构建时生成已有公开文章，因此新文章和草稿可能没有可访问的编辑地址；Pages 与 Workers 使用各自默认域名时属于跨站请求，浏览器可能拒绝现有的认证 Cookie。

本轮不增加重型编辑器、对象存储或统计平台，重点保证“登录、写作、保存、再次编辑”在本地和 Cloudflare 默认域名下都可用，并改善误操作保护与反馈。

## 方案

### 认证数据流

登录接口继续设置 HttpOnly Cookie，兼容自定义同站域名；同时返回短期 Access Token 和可轮换的 Refresh Token，前端仅在当前标签页的 `sessionStorage` 中保存。管理端统一请求工具优先附加 Bearer Token。遇到 401 时，仅发起一次刷新请求，服务端验证刷新令牌、数据库记录和管理员状态，吊销旧令牌并返回新令牌；刷新失败才跳转登录页。

退出登录和修改密码会吊销该用户的刷新令牌。这样既兼容 Cookie，又能让 `pages.dev` 到 `workers.dev` 的默认部署正常工作，不把凭据持久保存在 `localStorage`。

### 静态编辑路由

删除依赖 `getStaticPaths()` 的 `/admin/posts/[id]`，改为固定静态页 `/admin/posts/edit?id=<id>`。页面加载后校验正整数 ID，再由管理 API 获取文章。文章列表与新建成功跳转统一使用该地址，因此新增文章、草稿和构建后创建的文章无需重新构建 Pages 即可编辑。

### 写作交互

新建页以 `sessionStorage` 保存未提交草稿，包含标题、正文、摘要、Slug、封面和发布选项；重新打开时显示恢复提示。输入采用短延迟保存，并显示“草稿已暂存”。创建成功后清除本地草稿。

新建和编辑页统一提供：Markdown 快捷工具栏、实时字数与阅读时间、保存中禁用状态、页面内错误提示、未保存离开确认，以及移动端可用的粘性操作栏。保持现有主题变量和编辑部风格，不增加客户端框架。

## 错误处理与安全边界

- 刷新令牌只接受 `token_use=refresh`，数据库中必须存在未吊销且未过期的 SHA-256 哈希。
- 刷新时检查用户仍为启用管理员，并采用令牌轮换降低重放风险。
- API 错误继续使用统一 `{ error: { code, message } }` 结构；前端在页面内反馈，不依赖阻塞式 `alert`。
- 编辑 ID 非法、文章不存在、会话失效分别给出明确反馈或跳转。
- 本地草稿只保存在当前标签页，不上传、不跨浏览器持久化，也不包含账号密码。

## 验收与测试

- API：登录、刷新、旧刷新令牌失效、退出吊销、无效令牌和停用用户测试。
- Web：令牌存取、401 单次刷新、刷新失败清理会话、草稿序列化等纯函数测试。
- 路由：生产构建只生成固定 `admin/posts/edit/index.html`，不再依赖文章 ID 构建静态页。
- 交互：浏览器检查登录页、文章列表、新建/编辑页的桌面和窄屏布局、键盘保存、恢复提示及错误状态。
- 全量执行 `pnpm check`、`pnpm test`、`pnpm build` 和 `git diff --check`。
