# 友链简化、网站数据备份与 RSS 修复设计

## 目标

删除单管理员博客中没有实际价值的友链审核和检查流程；在后台提供不依赖命令行的数据备份与恢复；保证 RSS 输出始终是合法 XML。

## 友链

- 后台添加的友链立即生效并触发 Pages 更新。
- 公开友链接口返回所有未删除友链，兼容此前处于 `pending` 的记录。
- 后台列表只显示站点、URL、描述、排序和编辑/删除操作。
- 数据库保留旧 `status`、`check_url_ok` 字段，避免破坏已有 D1，不再在产品界面使用。

## 数据备份

- 后台设置页提供“导出备份”和“导入备份”按钮，用户直接选择 JSON 文件，不需要命令行。
- 备份包括文章、分类、标签、文章关联、评论、友链和站点设置。
- 不导出管理员账号、密码哈希、Refresh Token、审计日志、IP 或 User-Agent。
- 图片存放在 Git 仓库 `public/images/`，不属于 Worker/D1 数据备份；文案中明确说明。
- 导入前完整校验格式、数量、唯一 ID 和关联关系，再替换现有内容；成功后触发 Pages 更新。
- 导入保留当前管理员账号，并将文章归属到执行导入的管理员。

## RSS

- RSS 根节点显式声明 `xmlns:content="http://purl.org/rss/1.0/modules/content/"`。
- 即使某篇文章正文 HTML 为空，`content:encoded` 也不会再成为未声明前缀。
- 增加 XML 字符串回归测试。

## 验收

- 新增友链保存后直接显示，不出现审核、状态、通过或链接检查。
- 可以从设置页下载 JSON，并在确认后重新导入恢复内容。
- 损坏或引用关系错误的备份在删除现有数据前返回 400。
- RSS XML 包含 `xmlns:content`，可被 XML 解析器正常读取。
