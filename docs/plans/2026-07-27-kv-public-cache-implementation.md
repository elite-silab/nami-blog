# KV 公开内容缓存实现记录

## 目标

使用 Cloudflare Workers KV 加速经常被访问的公开内容，减少重复的 D1 查询。D1 仍是唯一真实数据源；KV 只是可以删除和重建的加速副本。

## 缓存范围

使用 KV 缓存：

- 非搜索的文章列表
- 已发布的公开文章
- 分类和标签
- 友链
- 可公开的站点设置

始终直接读写 D1：

- 搜索和阅读量
- 评论和访客隐私
- 管理后台和登录认证
- 草稿、密钥和网站备份

## 读取方式

1. 先查找 KV 中的公开副本。
2. 如果已存在，直接返回。
3. 如果不存在，从 D1 读取，再将结果暂存到 KV。
4. KV 未启用或读写失败时，自动跳过缓存并读取 D1。

公开 API 使用 `X-Nami-Cache` 响应头帮助排查：

- `HIT`：本次来自 KV 缓存。
- `MISS`：KV 中没有，本次从 D1 读取。
- `BYPASS`：该请求不使用 KV。

## 内容更新

后台发布文章或修改公开设置后，会主动清理 `nami:public:v1:` 开头的公开缓存。清理失败不会将已经保存到 D1 的内容改成失败状态。

文章列表的缓存有效时间为 2 分钟，其他公开内容为 5 分钟。由于 KV 在全球传播需要时间，极少数地区可能短暂读到旧副本。

## 配置

根目录 `wrangler.jsonc` 只需声明名为 `CACHE` 的 KV 绑定。Wrangler 会在首次部署时自动配置缓存空间，用户不需要手动创建 KV，也不需要复制空间 ID。

## 验证结果

- 第一次读取返回 `MISS`，再次读取返回 `HIT`。
- 搜索返回 `BYPASS`。
- 公开内容保存后，下一次读取重新返回 `MISS`并包含新内容。
- KV 失败时可正常回退到 D1。
- 类型检查、全部测试、Worker 构建和 Wrangler 部署预检通过。
