# 本地零额外命令上手设计

> 生产初始化边界已由 `2026-07-26-dashboard-production-bootstrap-design.md` 扩展；本文保留本地开发设计背景。

## 目标

新手复制根目录 `.env.example` 为 `.env` 后，只需安装依赖并运行开发服务，不再单独执行 D1 迁移、管理员初始化或密钥生成命令。模板提供明确的本地默认值和首次登录信息。

## 数据库初始化

根目录增加 `predev` 生命周期脚本，在每次 `pnpm run dev` 前执行本地 D1 migration。Wrangler migration 具有幂等性，已经执行过的版本会跳过，因此不会覆盖文章、账号或设置。生产迁移仍必须显式执行，不与本地启动混用。

## 本地管理员首次登录

根目录 `.env` 增加 `ADMIN_INITIAL_PASSWORD`。登录接口仅在以下条件全部满足时创建管理员：

1. API 请求目标为 `localhost` 或 `127.0.0.1`；
2. 登录用户名为 `admin`；
3. 数据库中没有任何未删除的管理员；
4. 输入密码与 `ADMIN_INITIAL_PASSWORD` 完全一致。

创建时使用 bcrypt 12 轮保存密码哈希，邮箱使用本地占位地址。创建成功后继续正常登录，后续请求只验证数据库密码；修改 `.env` 不会重置已有管理员密码。生产域名永远不会触发此流程，即使错误配置了相同变量。

## 配置与文档

`.env.example` 按“新手常用 / 本地安全密钥 / 一般无需修改”分区，明确本地默认登录账号和密码。项目只增加实际读取的 `ADMIN_INITIAL_PASSWORD`，不加入 Agent、Telegram 或加密相关的无效变量。README 和小白指南删除单独的 `db:migrate`、`db:seed` 必做步骤，并保留高级手动命令供维护者使用。

## 验证

- 空本地数据库在生产域名请求下不能自动创建管理员。
- 空本地数据库使用模板账号密码登录时自动创建一个管理员。
- 初次创建后，错误密码无法登录，修改环境变量也不会覆盖数据库密码。
- `pnpm run dev` 自动迁移后，健康检查、登录和 Web 页面正常。
- 完整执行类型检查、测试、构建与秘密泄露扫描。
