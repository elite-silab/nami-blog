# 访客主题选择器设计

## 目标

在保留站长全站默认主题的同时，允许每位访客在前台选择自己喜欢的樱花、海洋或星空主题。访客偏好只保存在当前浏览器，不修改 D1，也不影响其他人。

## 方案对比

### 方案 A：访客本机覆盖（采用）

- 后台 `site_theme` 继续作为默认主题。
- 前台提供“跟随站点 / 樱花 / 海洋 / 星空”。
- 具体主题写入 `localStorage`，“跟随站点”删除该记录。
- 优点：无需登录、无需 API，访客之间完全隔离。

### 方案 B：仅提供三个具体主题

- 实现更少，但一旦选择就无法自动跟随站长之后的调整。
- 不采用，因为站点默认主题会失去长期意义。

### 方案 C：将每位访客偏好写入服务端

- 可以跨设备同步，但需要访客账号、Cookie 或指纹。
- 对轻量个人博客过度设计，还会增加隐私成本，不采用。

## 交互

### 桌面端

- 导航右侧增加“主题”按钮，与明暗模式相邻。
- 点击后打开小型面板，展示四个选项及当前选中状态。
- 选择后立即生效并关闭面板。
- 点击外部或按 `Escape` 关闭。

### 移动端

- 顶栏保留明暗按钮与菜单按钮。
- 展开菜单后，在导航链接下方直接展示四个主题选项，不再叠加第二层弹窗。
- 选择后菜单保持打开，方便用户继续预览或切换明暗模式。

## 数据流

```text
D1 site_theme
    └── 服务端输出 <html data-theme="...">
            └── Head 初始化脚本读取 localStorage
                    ├── 无有效偏好：保留 D1 默认值
                    └── 有效偏好：覆盖 data-theme
```

`nami-theme` 只允许 `sakura`、`ocean`、`starry`。其他值一律忽略，避免主题属性进入无样式状态。`nami-dark` 继续独立工作。

## 无障碍与异常处理

- 主题组使用 `radiogroup` / `radio` 语义和 `aria-checked`。
- 弹出按钮使用 `aria-expanded` 与 `aria-controls`。
- 本机存储不可用时，仍可在当前页面临时切换；刷新后回到站点默认值。
- 弹层不使用顶部彩色条，用主题色点和边框表达状态。
- 保留现有焦点样式和减少动效支持。

## 验收

1. 无访客偏好时，使用后台主题。
2. 选择三套主题均立即生效，刷新后保留。
3. 选择“跟随站点”后删除访客偏好并恢复后台默认。
4. 主题与明暗模式可任意组合。
5. 桌面弹层、移动菜单、键盘与点击外部操作正常。
6. 无首屏主题闪烁，无页面级横向滚动。
