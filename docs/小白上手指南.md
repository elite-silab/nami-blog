# 小白上手指南

这份指南面向第一次接触 Astro、Cloudflare Workers 或环境变量的用户。按照顺序操作即可，不需要先理解所有技术名词。

## 1. 先认识两个项目

本仓库包含两个独立应用：

| 应用 | 目录 | 本地地址 | 用途 |
| ---- | ---- | -------- | ---- |
| Web | `apps/web` | `http://localhost:4321` | 博客页面和管理后台界面 |
| API | `apps/api` | `http://localhost:8788` | 登录、文章、评论和 D1 数据库接口 |

Web 会访问 API。正常启动后，需要同时保持两个服务运行；根目录的 `pnpm run dev` 会一次启动它们。

> 从旧版本升级？把 `apps/api/.dev.vars` 中的两个 JWT 密钥和 `apps/web/.env` 中的两个 URL 合并到根目录 `.env`，然后删除旧文件。不要复制旧模板中未使用的占位变量。

## 2. 为什么只使用根目录 `.env`

API 和 Web 都从项目根目录读取同一个 `.env`，这样只需要认识和编辑一个文件。

| 变量 | 用途 | 能否公开 |
| ---- | ---- | -------- |
| `ADMIN_INITIAL_PASSWORD` | 空数据库首次登录密码 | 真实值不能公开（模板值仅限本地） |
| `JWT_SECRET` | Access Token 签名 | 不能公开 |
| `JWT_REFRESH_SECRET` | Refresh Token 签名 | 不能公开 |
| `PUBLIC_API_URL` | 浏览器访问 Workers 的地址 | 可以公开 |
| `SITE_URL` | 站点域名、SEO 和 Sitemap | 可以公开 |

Astro 只会把 `PUBLIC_` 开头的变量放进浏览器代码，因此 JWT 密钥虽然与 Web 地址写在同一个文件里，也不会暴露给访客。

## 3. 用编辑器准备配置

以 VS Code 为例：

1. 在左侧文件树找到项目根目录的 `.env.example`。
2. 右键选择“复制”，然后在根目录“粘贴”。
3. 将副本重命名为 `.env`。
4. 本地使用默认端口时，文件内容无需修改，直接保存即可。
5. 如果修改了 API 或 Web 端口，再调整对应 URL。

完成后的结构应该是：

```text
nami-blog/
  .env.example   # 示例文件，保留不改
  .env           # 你的本地配置，不会提交到 Git
  apps/
```

文件内容示例：

```dotenv
ADMIN_INITIAL_PASSWORD=nami-local-admin
PUBLIC_API_URL=http://localhost:8788
SITE_URL=http://localhost:4321
JWT_SECRET=nami-local-only-access-secret-never-use-in-production
JWT_REFRESH_SECRET=nami-local-only-refresh-secret-never-use-in-production
```

模板中的值只允许本地开发使用。部署生产环境时，请使用密码管理器生成两个不同的 JWT Secret，并另外设置一个至少 12 个字符的一次性管理员密码，全部填写到 Cloudflare Dashboard；不要把生产 Secret 写回 `.env`。

## 4. 哪些配置会进入浏览器

只有 `PUBLIC_` 开头的变量会被打包进浏览器。目前是 `PUBLIC_API_URL`。这里绝对不能填写 JWT 密钥、Cloudflare API Token 或数据库密码。

Wrangler 通过启动参数读取根目录 `.env`，Astro 通过 `envDir` 读取同一个文件；用户不需要执行同步或复制命令。

## 5. 第一次启动

打开编辑器底部的终端，在项目根目录依次运行：

```bash
pnpm install
pnpm run dev
```

第一条命令安装依赖，第二条命令会先自动初始化本地数据库，再同时启动 API 和 Web。以后再次启动只需运行 `pnpm run dev`。看到以下地址说明启动成功：

```text
API: http://localhost:8788
Web: http://localhost:4321
```

在浏览器打开 `http://localhost:4321` 即可查看博客。

### 创建第一个管理员

1. 在浏览器打开 `http://localhost:4321/admin/login`。
2. 用户名填写 `admin`。
3. 密码填写根目录 `.env` 中 `ADMIN_INITIAL_PASSWORD` 后面的内容。
4. 首次登录后，在“后台设置 → 安全设置”中换成自己的密码。

本地 API 运行在 `localhost` 或 `127.0.0.1` 且数据库还没有管理员时，系统会自动创建这个账号。密码会加密保存；之后修改 `.env` 不会重置已有管理员。

已有管理员或需要手动创建额外账号的维护者，仍可使用高级命令 `pnpm run db:seed`；新手第一次本地使用不需要执行它。

## 6. 部署到 Cloudflare 时填写什么

### Workers 项目

在 Cloudflare Dashboard 的 Workers 项目中配置：

| 名称 | 类型 | 说明 |
| ---- | ---- | ---- |
| `JWT_SECRET` | Secret | Access Token 签名密钥 |
| `JWT_REFRESH_SECRET` | Secret | Refresh Token 签名密钥，必须与上面不同 |
| `ADMIN_INITIAL_PASSWORD` | Secret | 自己设置的一次性生产管理员密码，至少 12 个字符 |

`SITE_NAME` 和 `CORS_ORIGIN` 在 `apps/api/wrangler.toml` 中配置。部署前把 `CORS_ORIGIN` 改为实际 Pages 域名，并填写真实 D1 `database_id`。

生产环境会拒绝本地默认密码 `nami-local-admin`。首次使用自定义 Secret 登录后，立即在后台修改密码，并从 Workers Dashboard 删除 `ADMIN_INITIAL_PASSWORD`；已有管理员不会被 Secret 重置。

### Pages 项目

在 Cloudflare Pages 的 Settings → Environment variables 中配置：

| 名称 | 示例 |
| ---- | ---- |
| `PUBLIC_API_URL` | `https://api.example.com` |
| `SITE_URL` | `https://blog.example.com` |

Pages 中不要配置 JWT 密钥。生产配置优先填写在 Cloudflare Dashboard，不要创建并提交生产 `.env` 文件。

## 7. 常见问题

### 页面能打开，但没有文章

Astro 使用 SSG。构建时 API 没有运行或没有公开文章时，页面会显示空状态。确认 API 正常、文章状态为 `published` 且 `is_public = 1`，然后重新构建 Web。

### 浏览器提示 API 连接失败

确认终端中 API 正在 `8788` 端口运行。如果修改过端口，请检查根目录 `.env` 的 `PUBLIC_API_URL`，修改后重新启动开发服务。

### 修改配置后没有生效

停止当前开发服务，再重新运行 `pnpm run dev`。环境变量通常只在启动或构建时读取。

### `.env` 为什么在 Git 中看不到

这是正常的。真实配置文件包含本地秘密，已被 `.gitignore` 排除；仓库只提交 `.env.example` 模板。

### 可以把两个 JWT 密钥写成一样吗

不建议。Access Token 和 Refresh Token 用途不同，使用两段不同的随机值可以降低单个密钥泄露造成的影响。
