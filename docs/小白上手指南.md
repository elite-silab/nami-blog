# Nami Blog 小白上手指南

这份文档只讲日常使用。部署请看 [Cloudflare 部署指南](Cloudflare部署指南.md)。

## 先认识三个地址

官方实例：

- 博客首页：`https://nami-blog.codeelite.workers.dev`
- 管理后台：`https://nami-blog.codeelite.workers.dev/admin/login`
- 健康检查：`https://nami-blog.codeelite.workers.dev/api/v1/healthz`

它们都来自同一个 Cloudflare Worker。没有单独的 API 地址，也没有 Pages 地址。

## 在自己电脑上运行

先安装 Node.js 22 和 pnpm 9，然后在终端执行：

```bash
git clone https://github.com/elite-silab/nami-blog.git && cd nami-blog
pnpm install && cp .env.example .env
pnpm dev
```

浏览器打开 `http://localhost:4322`。

第一次运行会自动创建本地 D1 数据库。后台用户名是 `admin`，初始密码写在根目录 `.env` 的 `ADMIN_INITIAL_PASSWORD`。

### 怎样修改本地配置

用 VS Code 等编辑器直接打开项目根目录 `.env`，改完保存并重新运行 `pnpm dev` 即可。

项目只使用这一份本地 `.env`：

- 不需要 `.dev.vars`
- 不需要 `apps/api/.env`
- 不需要 `apps/web/.env`
- 不需要用 `echo` 命令写配置

`.env` 已被 Git 忽略，不会正常提交到 GitHub。仍然不要把它复制到聊天、Issue 或截图中。

## 登录管理后台

点击首页底部或直接访问 `/admin/login`。

- 用户名：`admin`
- 本地密码：根目录 `.env` 中的 `ADMIN_INITIAL_PASSWORD`
- 线上密码：Cloudflare 中设置的 `ADMIN_INITIAL_PASSWORD` Secret

如果是空数据库，第一次成功登录会自动创建管理员。创建后再修改 `.env` 或 Cloudflare 初始密码不会重置管理员密码；请在后台“站点设置”中修改。

## 写第一篇文章

1. 打开 **文章管理**。
2. 点击 **新建文章**。
3. 输入标题。
4. 在正文区使用 Markdown 写作。
5. 根据需要填写 Slug、摘要、分类、标签和封面图 URL。
6. 点击 **发布文章**。

发布前确认：

- 状态为“已发布”
- “公开”已勾选

发布成功后，前台会立即显示，不需要重新部署。

### Slug 是什么

Slug 是文章网址最后一段。例如 Slug 为 `hello-nami`，文章地址就是：

```text
/blog/hello-nami
```

推荐使用小写英文、数字和连字符。标题输入后系统会自动生成，也可以手动修改。

### 写作保护

- 新文章会在当前浏览器标签页临时保存草稿
- `Ctrl + S` 或 macOS 的 `Command + S` 可以快速保存
- 页面有未保存内容时，关闭前会提醒
- 临时草稿只保存在当前标签页，不等于云端草稿，重要内容仍要点击“保存草稿”

## 分类和标签

分类适合较大的主题，例如：

- 名称：技术随笔
- Slug：`tech-notes`
- 描述：记录开发实践、问题排查与工具心得

标签适合更具体的关键词，例如：

- 名称：Cloudflare
- Slug：`cloudflare`

新建和编辑弹窗会在页面中央显示。点击背景、右上角关闭按钮或“取消”即可关闭。

## 友链

后台添加的友链由站长直接管理，因此保存后立即公开：

- 没有“待审核”流程
- 没有“是否通过”开关
- 没有额外的链接检查步骤

填写名称、URL、头像 URL 和描述即可。

## 评论

访客提交评论后：

- 开启自动批准：立即显示
- 未开启自动批准：进入后台待审核列表
- 关闭评论：文章页不显示评论区，API 也会拒绝新评论

在 **站点设置 → 评论** 中修改开关，保存后前台立即生效。

## 网站设置

后台可以修改：

- 网站名称与副标题
- SEO 描述
- GitHub、Twitter/X 和邮箱
- 樱花、海洋、星空三套主题
- 评论开关、自动批准和敏感词

这些设置存放在 D1，保存后立即生效，不需要部署。

`NEXT_PUBLIC_SITE_URL` 不属于日常网站设置。它决定 SEO、RSS 和 Sitemap 使用哪个正式域名，只有换域名时才需要修改 `wrangler.jsonc` 并部署一次。

## 备份与恢复

进入 **站点设置 → 网站数据备份**：

- 点击“导出备份”下载 JSON 文件
- 点击“选择备份文件”选择以前导出的 JSON
- 点击“导入并替换数据”恢复

备份包含文章、分类、标签、关联关系、评论、友链和公开设置，不包含管理员密码、JWT 密钥、Cookie、IP 日志和仓库里的图片。

导入会替换当前网站内容。建议先导出当前备份，再执行导入。

## 阅读统计和存储用量

- “总浏览量”是公开文章阅读次数的合计
- 同一个标签页重复刷新同一文章不会反复上报阅读
- “存储用量”如果没有可靠的 Cloudflare 配额 API，就不应显示伪造数字；当前后台以真实可计算的数据为准

## RSS

RSS 地址为“站点地址 + `/rss.xml`”：

```text
https://nami-blog.codeelite.workers.dev/rss.xml
```

浏览器直接打开 XML 可能以纯文本显示，这是正常的。可以把地址加入 Feedly、Inoreader、NetNewsWire 等阅读器。

## 哪些修改需要部署

不需要部署：

- 文章、分类、标签、评论、友链
- 网站名称、副标题、SEO 文案、主题和评论设置
- 备份导入

需要部署：

- 修改代码或依赖
- 修改 D1/Assets 等 Worker 绑定
- 更换 `NEXT_PUBLIC_SITE_URL`
- 绑定新域名后更新 SEO 正式地址

## 常见问题

### 后台保存了文章，前台看不到

检查文章是否“已发布”并勾选“公开”。单 Worker 版本不需要重新部署。

### 登录提示服务暂时不可用

先访问 `/api/v1/healthz`。如果健康检查正常，再检查 D1 migrations 和三个 Cloudflare Secret。详细步骤见部署指南。

### 修改 `.env` 后密码没有变化

初始密码只在空数据库第一次登录时使用。已有管理员请在后台修改密码。

### 换了自己的域名

把根目录 `wrangler.jsonc` 中的 `NEXT_PUBLIC_SITE_URL` 改成自己的完整 HTTPS 域名并部署一次。以后发布内容仍不需要部署。
